SecureText

A console messenger handed out deliberately broken. Over three assignments I attacked each weakness, fixed it, and verified the fix, ending with end-to-end encryption where the server only ever sees ciphertext.

Type
ECE 572 graduate assignment series, individual
Language
Python, cryptography library
Focus
Password storage, message integrity, authentication, Zero Trust, E2EE
Source
Private (graded coursework)

Attack, then fix

Each task followed the same loop: reproduce the weakness with a working proof of concept, implement a fix with a reviewed library rather than a hand-rolled primitive, then show that the original attack no longer works.

End-to-end encryption

  1. Key agreementEach pair of users runs ECDH on the P-256 curve.
  2. Key derivationThe shared secret goes through HKDF-SHA256 to derive the message key, never used directly.
  3. Authenticated encryptionMessages are encrypted with AES-256-GCM, so tampering is detected, not just hidden. The server routes ciphertext it cannot read.
  4. Session hygieneSessions expire on a timer and their key material is cleared, limiting what a later compromise can expose.

The point I took from it: the cryptography was the easy part. Most of the effort went into everything around it, including key lifetime, error paths that leak nothing, and keeping secrets out of logs and source control.
