Forensic investigations

Three investigations from ECE 570 Computer Forensics Methodologies: ransomware in a memory image, a blackmail case on a laptop disk image, and a malware infection reconstructed from network traffic.

Type
Graduate coursework, University of Victoria, 2026
My role
Disk and network investigations individually; memory investigation as part of a team
Tools
Volatility 2 and 3, Autopsy, Wireshark, NetworkMiner, FTK Imager records, HxD
Environment
Kali Linux in an isolated virtual lab

The cases are course-provided training scenarios. Reports and evidence files are kept private, so this page describes method and findings rather than reproducing the submissions.

The method I follow

The same discipline applied to all three cases: a conclusion is only as strong as the evidence chain under it, and what was observed is kept separate from what was inferred.

  1. Verify integrity before analysisRecompute MD5 and SHA-1 hashes of every evidence file and compare them with the acquisition record. Nothing is examined until they match.
  2. Profile the systemEstablish operating system, users, hosts and time zone, so every later timestamp and artefact is interpreted correctly.
  3. Analyse, then corroborateEach finding is confirmed by a second, independent source: a second tool, a different artefact type, or a hash lookup against threat intelligence.
  4. Reconstruct the timelineOrder the corroborated events into a sequence that explains what happened, not a list of disconnected observations.
  5. Report with confidence levelsState facts, inferences and gaps separately, with the commands and frames that support each one.

Case files

Network: an Emotet infection

Individual, packet capture

A packet capture from a corporate network, about 50 minutes long. The task: find the infected host, how it was infected, and what it talked to afterwards.

  • Host attribution. Identified the victim's IP, hostname, MAC address and vendor, Active Directory domain and logged-in user from NBNS, DHCP, Kerberos and SMB2/NTLMSSP traffic, then confirmed them with NetworkMiner's passive fingerprinting.
  • Infection chain. Traced an HTTP download of a Word document with an auto-running, obfuscated macro, followed immediately by a second request that delivered a Windows executable. Both files were reconstructed from the TCP streams with Wireshark and, independently, NetworkMiner.
  • Identification without redistribution. Looked up the files' SHA-256 hashes on VirusTotal instead of uploading the samples. The document was flagged by 50 of 63 engines and the executable by 64 of 72, both as Emotet.
  • Command and control. Documented repeated HTTP POST beaconing to two external servers with randomised paths, including a callback that returned the victim's public IP, a known Emotet behaviour. Delivered hash-based indicators and remediation recommendations.

Disk and memory: a blackmail investigation

Individual, SSD image and memory dump

A suspect's laptop, imaged with FTK Imager, plus a memory capture. The task: establish who the suspect was communicating with, and whether there was evidence of blackmail and planned travel.

  • Integrity first. Recomputed MD5 and SHA-1 for the disk image and the memory dump and matched them to the acquisition log; added SHA-256 for extra assurance.
  • Mail and cloud artefacts. Parsed 495 emails with Autopsy, recovered deleted messages that contradicted the suspect's statement, and found an IMAP mail configuration and OneDrive sync confirmed by the OneDrive process in the memory dump (Volatility 3).
  • Hidden and encrypted files. Identified an attachment as an encrypted container by its file header rather than its extension, and found a 7-Zip archive disguised as a JPEG through its file signature in a hex editor.
  • Encoded evidence. Booking confirmations were Base64-encoded inside HTML mail bodies and unreadable in Autopsy; extracting the raw mailbox and decoding it recovered the travel details.

Memory: WannaCry ransomware

Team, Windows 7 memory image

A memory image from an infected Windows 7 machine, analysed with Volatility 2.6 on Kali Linux.

  • Process chain. pslist and pstree showed a randomly named executable launched by Explorer from the user's desktop, which spawned the WannaCry decryptor and its bundled Tor client.
  • Injected code. dlllist, ldrmodules and malfind surfaced memory regions marked PAGE_EXECUTE_READWRITE, a common sign of code injection.
  • Confirmation. Extracted the executable with procdump; VirusTotal flagged it as WannaCry (61 of 71 engines). Handle analysis found the ransomware's .eky and .WNCRYT working files.
  • Network and persistence. netscan found connections to an address that AlienVault OTX identifies as a Tor node; hivelist located the user registry hive for persistence analysis.

What carries over

The same habits appear in my engineering work. Verifying evidence before analysing it has a counterpart in SecureMind's strict validation before ingestion. Corroborating every finding with a second source is what its citation gate asks of AI reports. Looking up hashes instead of uploading samples is the same caution that keeps PhishGuard's dissector from ever fetching a URL.
